# Обёртка над Keitaro

Две части: создаватор кампании и редактор потоков. Кампания создаётся сразу в Keitaro. Правки офферов уходят в Keitaro только по кнопке Push.

Нужен Python 3.11 или новее.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --reload
```

На Windows виртуальное окружение включается так: `.venv\Scripts\activate`. Файл `.env` копируется командой `copy .env.example .env`.

После запуска откройте http://127.0.0.1:8000 .

`alembic upgrade head` создаёт локальную базу SQLite из `DATABASE_URL`. В ней лежат кампании, потоки и черновик офферов. Файл базы в git не входит.

## Настройки

Секреты только в своём `.env`, его нет в репозитории. Пример полей лежит в `.env.example`.

- `KEITARO_BASE_URL` — адрес трекера, без `/admin_api`.
- `KEITARO_API_KEY` — ключ из профиля Keitaro, раздел API-ключей. Пустой ключ запросы не выполняет.
- `KEITARO_DOMAIN_NAME`, `KEITARO_GROUP_NAME`, `KEITARO_SOURCE_NAME` — имена домена, группы и источника. При создании кампании их id ищутся в API, в код они не зашиты.

## Создаватор

На главной странице три поля: Name, Geo и Offer.

Имя должно начинаться с `test_`. Гео — коды стран через запятую, например `AU` или `MX,AU`. Оффер выбирается из поиска: запрос идёт в нашу ручку, она читает офферы Keitaro.

Create создаёт кампанию с ротацией по позиции, моделью затрат CPC, стоимостью 0 и галочкой «из параметра cost». Потоков два. Первый принимает указанное гео и ведёт на `https://google.com`. Второй без фильтра страны ведёт на выбранный оффер со долей 100%. После создания на странице есть ссылка в админку и ссылка на редактор потоков.

## Редактор

Страница кампании показывает потоки. Поток без офферов виден только заголовком: редирект и фильтры не разбираются. Поток с офферами показывает имена и целые доли.

- **Fetch streams from KT** заново читает потоки. Это состояние становится и экраном, и последним снимком, поэтому поток белый. Неопубликованный черновик Fetch затирает. Оффер, который обёртка уже знала и которого в Keitaro больше нет, остаётся серой строкой со долей 0%. Пин у оффера, который в потоке остался, сохраняется.
- **Add** добавляет оффер, пересчитывает доли и делает поток жёлтым. Появляются Push to KT и Cancel.
- **Push to KT** отправляет в Keitaro только активные офферы и их доли, затем записывает этот состав как снимок. Поток снова белый.
- **Cancel** возвращает поток к последнему Fetch или Push. Привязка, которой в снимке не было, исчезает. Сам оффер в справочнике остаётся.
- **Remove** не удаляет строку. Доля становится 0%, строка сереет, кнопка меняется на Bring back, остальные активные доли пересчитываются. После Push этого оффера в Keitaro нет, в обёртке он остаётся.
- **Bring back** возвращает снятый оффер в активные. Поток снова жёлтый, в Keitaro оффер попадает следующим Push.
- **Pin** закрепляет текущий процент. Дальше пересчитываются только незакреплённые активные офферы. Остаток до 100 делится поровну, лишний процент получает первый незакреплённый в списке. Сумма пинов больше 100 не принимается.

Пока экран совпадает со снимком, кнопок Push и Cancel нет. Жёлтый фон значит, что правка ещё не отправлена в Keitaro.
